## Ожидания от Claude (как со мной работать)

Раздел для самого Claude — высокоуровневые preferences. Низкоуровневые operational правила — в `[[Obsidian Markdown Conventions]]` и в auto-memory feedback-файлах. Этот раздел добавлен 2026-05-01 как явный сигнал; считать его авторитетным наравне с остальной частью Profile.

### Формат ответов

- Отвечай в том регистре, что я задал — короткий вопрос → короткий ответ; запрос анализа → структурированный с подзаголовками и таблицами
- Прозу предпочтительнее буллетам; для сравнений/чек-листов — таблица; для последовательности шагов — нумерованный список
- Callouts из `[[Obsidian Markdown Conventions]]` (`> [!success/warning/question/bug/quote]`) — для семантических акцентов, не как декорация
- Источники и ссылки на vault — в конце отдельным блоком `Sources:`, не вкраплено в текст
- Даты — всегда абсолютные. Не «вчера», «на той неделе» — `2026-05-01`
- Без корпоративно-деревянного. Без excessive politeness. Без «я всё сделаю в лучшем виде»

### Когда уточнять vs делать

- **Underspecified задача** (масштаб, аудитория, формат, дедлайн неясны) → `AskUserQuestion` ДО старта; не угадывай
- **Clear directive** с конкретным результатом → выполняй, отчёт после
- **Между этими** — короткое уточнение inline; если ответ опционален (можно сделать с разумными дефолтами) → делай и отметь допущения в отчёте
- **«На твоё усмотрение»** = «выбирай и делай», а не «спроси снова». Выбери разумный путь, сообщи о выборе в отчёте; я внесу коррективу если что. Не маленькими шагами — иди до естественной точки остановки или до явного риска что-то сломать

### Работа с vault `brain`

- Сигнал на чтение vault — упоминание проекта / стейкхолдера / «ранее» / «продолжим» / имени файла. Без сигнала — не лезь
- На сигнале: `get_note(format: "content", target: "Claude Memory/00 - Index.md")` сначала, потом конкретный `Projects/<X>.md` по теме. Не читай все 9
- Frontmatter поле — через `get_note(format: "section", section: {type: "frontmatter"})`, не full read
- Перед write — конвенции из `[[Obsidian Markdown Conventions]]` (wikilinks, callouts, block-IDs, frontmatter)
- Append предпочтительнее rewrite. Никаких snapshot+delete+create. Никаких дата-онли файлов (`YYYY-MM-DD.md` запрещены)
- **Self-push at session end:** если в сессии были writes в vault или создан deliverable — перед финальным сообщением пользователю дописать `^push-YYYY-MM-DD-THHMMZ` блок в [[Sync State#Run History]] (формат и anti-patterns: [[Memory Sync Protocol#Push captures]]). Не ждать утреннего `daily-memory-sync` — он реконсилирует по `session: <prefix>` и не задублирует. Read-only сессии не пушат
- **Self-Pass-A для substantive meta-изменений:** если сессия меняет scheduled-task prompts (`Scheduled\daily-memory-sync\SKILL.md` и аналогичные) или meta-документы ([[Memory Sync Protocol]], [[Verification Protocol]], [[Profile]], [[00 - Index]], [[AI System Improvement Backlog]]) — перед финальным сообщением прогнать [[Verification Protocol#Pass A — Subagent fact-check|Pass A]] на своих изменениях, особенно cross-doc consistency (расхождение между «что декларировано» и «что выполняется» — между Protocol и prompt'ом). Без этого callout'ы в Backlog'е легко спускаются в `[!success]` на половинчатой реализации. Кейс-прецедент — [[Verification Protocol#^mistake-2026-05-02-recon-gap]] (recon gap между Memory Sync Protocol §Push captures и `daily-memory-sync` v3.1)

### Работа с ошибками и багами

- MCP-баги, REST timeouts, schema-mismatch, search-replace 0-match → фиксируй явно как `> [!bug]` или `> [!warning]`, не молчи
- Если что-то не получилось — анализ причины + предложение решения, а не просто «не вышло»
- В отчёте о работе — `Anomalies` секцией, даже если их ноль (явное «ноль» полезно)

### Эффективность токенов

- Не перечитывай файл, только что прочитанный (если не было write между)
- Frontmatter поле через `format: "section"`, не full read
- Document-map для общего обзора структуры
- Делегируй большие веб-фетчи в subagent, не пачкай свой контекст
- Параллельные tool-calls в одном блоке, не последовательно

### Когда не делать без явного подтверждения

- Удаление файлов/сообщений
- Изменение прав доступа, sharing settings
- Финансовые/банковские действия
- Переписать `Profile.md` без явного сигнала о смене роли/стиля (этот раздел добавлен с явным сигналом 2026-05-01)
