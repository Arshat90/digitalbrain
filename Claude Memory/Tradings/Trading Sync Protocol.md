# Trading Sync Protocol

Синхронизация торгового состояния между ==параллельными сессиями Claude== (Dispatch и Cowork) через общий vault. Расширение [[Memory Sync Protocol]] на домен трейдинга; не заменяет его.

> [!abstract] Суть
> Обе сессии — разные процессы Claude, они не делят контекст. Единственная общая среда — этот vault (`obsidian-rest` → REST endpoint `http://127.0.0.1:27123`). Значит источник правды по портфелю = один файл [[Portfolio State]], который обе сессии **читают первым** и **пишут сразу** при изменении.

## Почему это нужно

Push-захваты в [[Sync State]] уже пишут историю торговых сессий (обеих surface'ов), но это хронологический аудит-лог, разбросанный по датам — новая сессия не восстановит из него «что открыто прямо сейчас». [[Portfolio State]] закрывает этот разрыв: единый живой снапшот текущего состояния.

## Субстрат

- Обе surface'а (Dispatch и Cowork) имеют коннектор `obsidian-rest`, настроенный на ==один и тот же vault и REST endpoint==. Это обязательное условие — если Dispatch пишет в другой vault, синхронизации нет.
- Живой Obsidian + Local REST API plugin нужен **в момент чтения/записи** (см. [[Memory Sync Protocol#Post-reboot verification]]).

## Контракт (обе сессии обязаны)

1. **Read-first.** В начале любой торговой работы (триггер `ТА:`, «полный/короткий анализ», ревизия позиций) — прочитать [[Portfolio State]]. Это даёт открытые позиции, риск, сетапы, последний чекпоинт.
2. **Reconcile.** Сверить снапшот с живым счётом (`bybit_snapshot` / счёт). Разошлось → обновить снапшот и `state_version +1` перед решением. Если `reconciled_with_live: false` — сверка обязательна.
3. **Write-on-change.** Любое изменение (филл, закрытие, БУ, новый сетап, движение equity):
   1. Дописать строку в `## Журнал сделок` (append-only, block-ID `^ev-YYYY-MM-DD-<slug>`).
   2. Обновить снапшот сверху + frontmatter: `state_version +1`, `state_updated_utc` (UTC now), `state_updated_by: dispatch | cowork`.
4. **trade_calc-гейт.** Числа сделки (размер, SL-флор, R/R) — только через `trade_calc`, не «на глаз».
5. **Push-захват сохраняется.** Раз сессия писала в vault ([[Portfolio State]]) — срабатывает Триггер 1 [[Memory Sync Protocol#Push captures]] → перед финальным сообщением дописать push-блок в [[Sync State]]. Meta-аудит продолжает работать как раньше.

## Две дорожки данных

| Слой | Где | Модель записи |
|------|-----|---------------|
| Текущее состояние | верх [[Portfolio State]] + frontmatter | ==last-writer-wins== (перезапись снапшота) |
| История сделок | `## Журнал сделок` внизу | ==append-only==, никогда не затирать |
| Meta-аудит сессий | [[Sync State]] `## Run History` | push-захваты (auto, как для всех проектов) |

## Параллельные записи (конфликты)

Обе сессии пишут через единственный REST endpoint — он сериализует операции (не транзакции, best-effort; та же модель, что в [[Memory Sync Protocol#Concurrency и known limitations]]).

> [!warning] Staleness-детект через версию
> Читаешь снапшот с `state_version: N`. Перед записью своего апдейта — быстро перечитай frontmatter. Если версия уже `>N` (другая сессия успела записать) — ==перечитай снапшот и слей== своё изменение поверх свежего, только потом пиши `N+1`. Это защищает от затирания чужого апдейта.

- **Снапшот** — last-writer-wins, поэтому staleness-детект обязателен.
- **Журнал** — append-only: параллельные дописи не конфликтуют (обе строки остаются), даже если снапшот перезаписался.
- **Чекпоинты** (плановые перезаписи снапшота 06/12/18:30/23) остаются за сессией-владельцем по расписанию (Opus), как в [[trading-checkpoints-opus-binding]]. Ad-hoc сессии Dispatch/Cowork в промежутке только дописывают журнал + инкрементят версию.
- **Корр-кластер = 1 позиция:** проверять по снапшоту перед новым входом (не открывать второй коррелирующий вход, пока первый не в БУ).

## Что нужно на стороне Dispatch

Чтобы Dispatch реально следовал контракту (а не только имел доступ), его инструкции/скилл должны содержать: «в трейдинге читать [[Portfolio State]] первым и писать при изменении». В Cowork это уже зашито в память проекта; на стороне Dispatch — добавить ту же строку в его системный промпт/скилл трейдинга. Иначе Dispatch будет видеть файл, но не обновлять его дисциплинированно.
